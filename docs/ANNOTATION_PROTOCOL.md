# AI预标注和人工审核执行协议

## 基本标签
- **R**：抗风险、控制损害、在冲击下维持关键功能。
- **C**：已受损/受困功能的恢复救助，或预案中具体假设中断后的恢复。
- **A**：因变化的环境或风险调整策略、标准、制度、资源或运行方式。
- **E**：面向受众提供独立的避险、求助、释疑、稳定预期或鼓舞信息。
- **Core**：R/C/A任一为1→1；全0→0；其他缺失情形→空；E不参与。

详细判定和证据条件以实际标注时使用的手册版本为准。

## 探索阶段与批量阶段
探索：少量真实片段可人工初判后AI复核，用于发现边界问题。
批量：所有片段先AI预标注（弱标签），再由人工优先复核高争议样本并独立随机抽查。不能把未经人工确认的机器标签记为gold。

## 本批160条的审核次序
1. 冻结原始Excel、doc_id、unit_id、文本及手册版本，保留初始weak预测。
2. **先完成26条随机审计盲表**。在提交盲审前不得查对应AI预测。逐项填写人工R/C/A/E、证据、裁决原因、日期和身份。
3. 再检查38条难例；可见AI建议，逐条对照文本、来源、上下文和争议理由后裁决。
4. 把结果分别记录为 `gold`（人工确认）、`weak`（模型预标注）、`unresolved`（未决）；保留两份标签，不能覆盖原机器结果。
5. 在有人工对照的有效样本上报告每维Precision/Recall/F1和有效例数，随机审计与刻意挑选难例分开报告，不把难例错误率外推。
6. BERT正式测试须按整篇公文/近重复组隔离，使用人工独立标注的测试片段；避免文档片段跨集合泄漏。

## 疑难优先
- 受损补偿C vs 保持运行R vs 普惠优惠全0。
- 既有预案执行R vs 新风险改变制度A。
- 救助指引E+C vs 仅政策发布C。
- 仅风险事实、一般发展措辞、能力不足、假设应急场景。
- 无典型关键词的真阳性，以及含“恢复”“调整”的常规负例。

## 信息质量
每个1需保留最短可定位原文证据；AI证据应在原文中核验。不得凭发布时点或行业同期受冲击自动补齐文本未表达的功能。跨时资料仅核实当时已经存在的事实。
